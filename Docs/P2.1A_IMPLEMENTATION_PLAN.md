# P2.1 Elemental Towers & Statuses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить четыре базовых стихийных архетипа с тремя уровнями, детерминированные статусы, каталог строительства и совместимые checkpoints без изменения legacy Test Tower.

**Architecture:** Чистый Domain владеет immutable tower catalog, статусами врага и единым damage/death pipeline. `BattleScenarioConfig` поставляет валидируемые данные; Presentation только выбирает `TowerDefinitionId`, вызывает команды и отображает snapshots. Infrastructure мигрирует schema 1 строго в `test-tower` и записывает schema 2.

**Tech Stack:** Unity 6000.3.28f1, C#, ScriptableObject/uGUI, Unity Test Framework NUnit EditMode/PlayMode, `UnityEngine.JsonUtility`.

## Global Constraints

- Следовать `Docs/P2.1A_ELEMENTAL_TOWERS.md`; все числа баланса — гипотезы для плейтестов.
- Не менять Unity/URP/packages, fixed 30 Hz, legacy Test Tower, Shade HP/speed/reward и REG-BATTLE-001…089.
- Domain сохраняет `noEngineReferences: true`; UI не изменяет HP/Gold/Grid/statuses напрямую.
- Реакции, гибриды, element unlocks, новые враги и глоссарий не входят в P2.1.
- Checkpoint schema 2 требует `towerTypeId`; schema 1 мигрирует только в `test-tower`, никогда в FLAME/первый элемент.
- Физические checkpoint slot names сохраняются; tests/QA используют temporary save root.
- Каждый PR: failing regression test → minimal implementation → targeted/full PASS → docs/evidence → commit → независимый review.

- [ ] **Step 3: Реализовать централизованные damage rules**

```csharp
private static int ApplyArmor(int damage, int armor, int penetration)
{
    var remainingArmor = Math.Max(0, armor - penetration);
    return Math.Max(1, damage - remainingArmor);
}

private static int ApplyGust(int damage, StatusInstance gust)
{
    if (gust == null) return damage;
    return (int)Math.Min(int.MaxValue,
        ((long)damage * (100 + gust.Power)) / 100);
}

var crackPower = enemy.Crack == null ? 0 : enemy.Crack.Power;
var effectiveArmor = Math.Max(0, enemy.Definition.Armor - crackPower);
var afterArmor = ApplyArmor(tower.Definition.Damage, effectiveArmor,
    tower.Definition.ArmorPenetration);
var directDamage = ApplyGust(afterArmor, enemy.Gust);
```

Direct pipeline: Crack → ArmorPenetration → Gust → HP → status only if alive. Burn: Crack → armor без penetration/Gust → HP. Все вычисления deterministic, без Unity APIs и новых collections на каждый тик.

```csharp
public void SelectTowerType(TowerDefinitionId id)
{
    if (!_hasSelection || _hasTowerSelection || battle.IsPaused) return;
    var archetype = battle.Simulation.TowerCatalog.Get(id);
    if (!archetype.ShowInCatalog) return;
    _selectedTowerTypeId = id;
    ShowSelectionVisual(SelectedCell, archetype.Levels[0].Range, isPlacement: true);
    RefreshUi();
}

public PlaceTowerResult PlaceTower(TowerDefinitionId id, GridCoordinate coordinate)
{
    if (IsPaused) return PlaceTowerResult.Failed(PlaceTowerFailureReason.InvalidPhase);
    var result = _simulation.PlaceTower(new PlaceTowerCommand(id, coordinate));
    if (result.Success && checkpointController != null)
        checkpointController.SaveCurrentState();
    return result;
}
```
