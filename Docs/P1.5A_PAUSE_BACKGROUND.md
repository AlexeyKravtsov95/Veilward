# P1.5a — Pause & Background: спецификация

## Scope и acceptance criteria

P1.5a добавляет ручную паузу и безопасное продолжение текущего матча после focus loss/background. Работа начинается от `origin/main` с merged PR #10 (`dc17cca`). Сохранение на диск, восстановление после завершения процесса, изменение баланса, новые игровые механики, Unity packages и физический device-test не входят в scope.

Готовый тикет должен обеспечить:

- Pause в Preparation, Combat и WaveComplete и простой landscape overlay с Resume;
- неизменность Phase, Tick, enemies, cooldown, HP, Gold, kills и wave transitions на протяжении паузы;
- блокировку placement, Upgrade, Sell, Start Wave и Next Wave как через UI, так и через соответствующие controller API;
- автоматическую паузу при `OnApplicationPause(true)` и `OnApplicationFocus(false)` без автоматического Resume;
- Resume только при активном приложении и наличии фокуса, идемпотентную обработку повторных и пересекающихся callbacks;
- отсутствие догоняющих тиков и сохранение детерминированного порядка последующих атак и наград;
- очистку незавершённого placement и Sell confirmation без экономических изменений;
- полноэкранную блокировку ввода и подавление сквозного нажатия Resume;
- сохранение Victory/Defeat и корректное освобождение подписок при закрытии сцены;
- реальные Play Mode screenshots паузы и продолжения, положительные полные quality gates и Console audit.

## Архитектура

### Единый источник состояния

Новый `BattlePauseController` находится в Presentation на `Battle Controller` GameObject и единолично владеет:

- `_isPaused` — защёлкнутое состояние паузы;
- `_applicationPaused` — последнее известное Unity application-pause состояние;
- `_hasFocus` — последнее известное focus состояние.

При создании foreground-сцены начальные значения: `_isPaused = false`, `_applicationPaused = false`, `_hasFocus = true`; последующие Unity callbacks заменяют lifecycle flags, но не снимают ручную паузу.

`BattleSceneController.IsPaused` только делегирует чтение `BattlePauseController.IsPaused`. `BattlePlacementController` читает то же свойство через `battle`. Domain не содержит pause flag, Unity lifecycle или новых игровых правил.

В saved Battle scene ссылки `BattlePauseController → BattleSceneController/BattlePlacementController/Pause Overlay/Pause Button/Resume Button` и `BattleSceneController → BattlePauseController` обязательны. Изолированные legacy EditMode fixtures могут создавать `BattleSceneController` без pause controller; в этом случае бой считается не paused. `BattleSceneBuilder` и `BattleAssetValidator` не допускают отсутствие pause wiring в сохранённой сцене.

### Переходы состояния

| Событие | Результат |
|---|---|
| `Pause()` в активном матче | `_isPaused = true`; повторный вызов ничего дополнительно не делает |
| `OnApplicationPause(true)` | `_applicationPaused = true`, затем `Pause()` |
| `OnApplicationPause(false)` | `_applicationPaused = false`; `_isPaused` сохраняется |
| `OnApplicationFocus(false)` | `_hasFocus = false`, затем `Pause()` |
| `OnApplicationFocus(true)` | `_hasFocus = true`; `_isPaused` сохраняется |
| `Resume()` при `_applicationPaused == false && _hasFocus == true` | `_isPaused = false`; один кадр pointer input подавляется |
| `Resume()` в background или без focus | возвращает `false`, состояние не меняется |
| Повторный `Resume()` | безопасен и не создаёт дополнительных переходов |

Возврат из background/focus никогда сам не снимает паузу. Ручная пауза, focus loss и background могут пересекаться в любом порядке; только явный успешный Resume снимает защёлку. Battle Phase при этом не копируется и не восстанавливается отдельно: он остаётся в неизменном `BattleSimulation.State`, поэтому Victory/Defeat не могут превратиться в Combat.

### Заморозка симуляции и эффектов

`BattleSceneController.Update()` при паузе не вызывает `BattleSimulation.Step()`, обнуляет accumulator и запоминает pause boundary. Первый Update после успешного Resume не накапливает `Time.deltaTime`; последующие кадры продолжают обычный fixed-step accumulator. Максимум steps per frame и существующий clamp сохраняются.

`AttackBeamView` получает ссылку на свой `BattleSceneController` при создании. Во время `IsPaused` его remaining lifetime не уменьшается; после Resume эффект продолжает оставшееся время. Глобальный `Time.timeScale` не изменяется.

`LateUpdate()` может синхронизировать существующие views и HUD, но не изменяет Domain. Никаких disk save/checkpoint операций в P1.5a нет.

### Блокировка команд

До вызова Domain `BattleSceneController.PlaceTower/UpgradeTower/SellTower` при паузе возвращают failed result с существующим `InvalidPhase`; `StartWave/ContinueToNextWave` возвращают `RejectedInvalidPhase`. Так сохраняются текущие result contracts без добавления pause semantics в Domain.

`BattlePlacementController` дополнительно блокирует `TrySelectCell`, `ConfirmSelection`, `UpgradeSelectedTower`, `RequestSellSelectedTower`, `ConfirmSellSelectedTower`, `StartWave` и `ContinueToNextWave`. Все игровые кнопки не interactable во время паузы. Cancel API может очищать presentation selection, но не выполняет игровую команду.

При rising edge паузы `BattlePauseController` вызывает `CancelSelection()`, который одновременно очищает pending Sell TowerId и confirmation. Поэтому после Resume старый Confirm Sell возвращает `ConfirmationRequired` и не меняет Gold/Grid.

### Pause overlay и ввод

Builder добавляет Pause button в верхнюю правую часть HUD рядом с wave controls. Полноэкранный `Pause Overlay` создаётся последним среди HUD siblings, имеет stretch anchors, полупрозрачный `Image` с `raycastTarget = true`, центрированную надпись `Paused` и `Resume Button`. Overlay активен только при `_isPaused`; Resume interactable только когда приложение активно и имеет focus.

`BattlePlacementController.Update()` не обрабатывает world pointer во время паузы. Успешный Resume дополнительно подавляет pointer handling на текущий кадр, поэтому тот же click/tap не выбирает клетку и не активирует скрытый control. EventSystem и GraphicRaycaster продолжают обслуживать Resume.

`OnDestroy` снимает listeners Pause/Resume. Существующие listeners placement также снимаются его `OnDestroy`; EnhancedTouch lifetime не расширяется. Scene-owned overlay и beams уничтожаются обычным scene lifecycle без статических подписок.

## Тестовая стратегия

### EditMode

Новые `BattlePauseTests` создают реальные controllers с serialized references и вызывают публичные command/lifecycle API. Проверяются state snapshots, rejected commands, pending Sell/selection, overlap ручной паузы с focus/background, Resume только при active/focused и terminal preservation. Отдельные builder/validator tests проверяют saved scene и повторяемую генерацию.

### PlayMode

Новый `BattlePausePlayModeTests` загружает saved `Battle` scene, выполняет реальные `Button.onClick.Invoke` для Pause/Resume и game controls, ждёт несколько кадров паузы и проверяет отсутствие Tick/enemy/cooldown/economy changes. Проверяются Preparation, Combat, WaveComplete, stale Sell confirmation, overlay и отсутствие сквозного world selection.

Для deterministic continuation фиксируются state и cooldown до паузы, затем после Resume выполняется та же последовательность explicit simulation ticks, что и в контрольном прогоне. AttackEvents, Gold, kills, HP и результат должны совпадать. Пауза не добавляет и не удаляет simulation ticks.

### Реальные визуальные доказательства

В `Docs/review/P1.5a/` сохраняются landscape Play Mode кадры как минимум: Preparation pause overlay, Combat pause с замороженным состоянием и продолжение после Resume. `qa.log` содержит точные действия, состояния до/во время/после паузы и ограничения метода. Console audit сохраняется отдельно; утверждение 0 errors допускается только по фактическому отчёту.

Обязательные команды:

```bash
./Scripts/run-static-checks.sh
./Scripts/run-edit-mode-tests.sh
./Scripts/run-play-mode-tests.sh
git diff --check
```

PASS требует non-empty total и нулевые failed/inconclusive/skipped. Unity CI, physical iPhone background/focus, built-player touch, safe area, signing и Simulator остаются NOT VERIFIED без фактических запусков. Editor Play Mode callbacks не выдаются за device verification.
