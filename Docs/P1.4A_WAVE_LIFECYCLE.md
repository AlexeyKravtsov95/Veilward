# P1.4a — Wave Lifecycle & Rewards: техническая спецификация

## Scope и acceptance criteria

Реализуется один вертикальный путь: последовательная симуляция восьми волн, ручные переходы, награды за kills и завершение волн, `Victory`/`Defeat`, минимальное расширение существующего Battle HUD. Upgrade/Sell, новые башни, новые пакеты, автозапуск, отдельная results-сцена и редизайн UI не входят.

Готовый тикет должен обеспечить:

- восемь Inspector-настраиваемых волн с количеством Shade `5, 6, 7, 8, 9, 10, 11, 12`;
- сохранение `TestWave.asset` и всех контрактов REG-BATTLE-001…008;
- запуск `EightWave.asset` в сохранённой Battle scene;
- неизменность состояния после недопустимых команд и в терминальных фазах;
- положительный полный результат static, EditMode, PlayMode и `git diff --check`;
- реальные Play Mode screenshots пяти требуемых состояний.

## Затронутые системы и риски

- Domain: `BattleSimulation`, `BattleState`, `IBattleSimulation`, результат wave-команд.
- Конфигурация: сериализованный список волн и ссылка восьмиволнового сценария на общую карту/бой `TestWave.asset`.
- Presentation: HUD и две существующие кнопки управления волной без изменения правил в Domain из UI.
- Editor: builder, validator и reproducibility snapshots для нового asset.
- Риски: случайный сброс глобальных ID/tick/cooldown, двойная выплата при повторных командах, изменение legacy-экономики, расхождение builder и сохранённой сцены, ложный visual PASS без реальных кадров.

## Конфигурация

`BattleScenarioConfig` сохраняет текущие serialized поля. Пустой `waves` означает legacy single-wave: один `WaveDefinition`, финальная фаза `WaveComplete`. Непустой `waves` использует новую последовательность и финальный `Victory`.

`EightWave.asset` содержит только собственную последовательность волн, `enemyReward = 5`, `waveCompletionBonus = 20` и ссылку `sharedScenario` на `TestWave.asset`. Путь, сетка, HP, стартовое золото, параметры Shade и Test Tower читаются через эту ссылку; координаты маршрута не копируются. Повторный Build не перезаписывает существующие настройки волн и экономики.

## State transition table

| Текущая фаза | Команда/условие | Результат |
|---|---|---|
| Preparation | `StartWave()` | Combat; spawn tick 0 текущей волны; WaveIndex не меняется |
| Preparation | повторный `StartWave()` после входа в Combat | `RejectedInvalidPhase`; состояние не меняется |
| Combat | `Step()`, волна не исчерпана | глобальный Tick +1; боевые стадии в прежнем порядке |
| Combat | все враги завершены, HP > 0, не последняя волна | бонус один раз; WaveComplete |
| Combat | все враги завершены, HP > 0, последняя новая волна | бонус один раз; Victory |
| Combat | HP = 0 | Defeat; бонус не начисляется, даже если врагов больше нет |
| WaveComplete | `ContinueToNextWave()`, есть следующая волна | WaveIndex +1 ровно один раз; Preparation |
| WaveComplete | повторный `ContinueToNextWave()` после перехода | `RejectedInvalidPhase`; состояние не меняется |
| WaveComplete | следующей волны нет (legacy) | `RejectedNoNextWave`; состояние не меняется |
| Victory / Defeat | `Step()`, `StartWave()`, `ContinueToNextWave()` | безопасный отказ/no-op; состояние не меняется |
| любая фаза, кроме Preparation | `PlaceTower()` | прежний `InvalidPhase`; состояние не меняется |

Между волнами `Step()` не выполняет боевой тик. Следующая волна запускается только отдельной командой `StartWave()` из Preparation.

## Spawn, ID и сохраняемость

- `WaveIndex` zero-based; `WaveCount` неизменен в течение матча.
- `_waveStartTick = State.Tick` фиксируется при успешном `StartWave()`.
- Абсолютный spawn tick: `_waveStartTick + FirstSpawnTick + spawnIndex * SpawnIntervalTicks` с long-арифметикой.
- `_nextSpawnIndex` сбрасывается только при успешном старте волны.
- `_nextEnemyId`, `_nextTowerId`, `State.Tick`, Tower `NextAttackTick`, Gold, BaseHealth, Kills и Towers не сбрасываются между волнами.

## Economy invariants

1. Kill reward равен `EnemyDefinition.Reward` и начисляется в той же операции удаления погибшего, что и `Kills += 1`.
2. Мёртвый EnemyId удаляется и оплачивается один раз; последующие атаки в том же тике пропускают мёртвую цель.
3. Leak удаляет врага, применяет только leak damage и не изменяет Gold/Kills.
4. Завершение волны начисляет configured bonus один раз; финальная победная волна получает его тоже.
5. `Defeat` имеет приоритет над WaveComplete/Victory и не даёт wave bonus.
6. Gold меняется только Domain. Debit остаётся атомарным и не допускает отрицательное значение.
7. Credit использует насыщение: `Gold = min(int.MaxValue, Gold + amount)` без signed overflow. Reward/bonus неотрицательны и валидируются.
8. Недостаток денег, occupied/blocked cell и любые rejected commands не меняют экономику или другое состояние.

## Порядок боевого тика

Сохраняется P1.3: **Advance Tick → Spawn → Movement/Leaks → Tower Attacks → Death/Removal + kill rewards → Defeat/WaveComplete/Victory + wave bonus**. `StartWave()` обрабатывает только due spawn и не атакует до первого `Step()`.

## UI contract

HUD отображает только Domain state: `Wave: current / count`, Base Health, Gold, Towers, Kills, Active Enemies, Tick, Phase и терминальный Result. Start Wave интерактивен только в Preparation; Next Wave только в WaveComplete при наличии следующей волны. Повторные нажатия проходят через идемпотентные Domain commands. Существующий mouse/touch placement flow не меняется.

## Regression и evidence

Новые REG-BATTLE-009…024 фиксируются в `Docs/REGRESSION.md` до реализации. Полный deterministic тест сравнивает snapshots и AttackEvents двух одинаковых восьмиволновых матчей. Legacy tests не подгоняются под новую экономику.

Quality gates: `./Scripts/run-static-checks.sh`, `./Scripts/run-edit-mode-tests.sh`, `./Scripts/run-play-mode-tests.sh`, `git diff --check`. Отдельно проверяются runtime compilation, missing scripts, `.meta`/GUID, отсутствие новых packages и посторонних Scene/Prefab изменений. В PR результаты делятся на VERIFIED и NOT VERIFIED / BLOCKED; физический iPhone не объявляется проверенным без device-теста.
