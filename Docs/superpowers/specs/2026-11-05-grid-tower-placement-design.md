# P1.2 — Grid & Tower Placement: технический дизайн

## Scope

Добавить в существующий Battle первую интерактивную механику строительства: сетку 12×8, блокировку клеток фиксированного маршрута, выбор клетки, preview тестовой башни, Confirm/Cancel, списание золота и ручной запуск существующей волны. Строительство разрешено только в `Preparation`. Атаки, улучшения, продажа, стихии, сохранения и новые пакеты не входят в задачу.

## Domain

`GridMapDefinition` хранит ширину, высоту, координатное начало и размер клетки. Он выполняет проверку границ и однозначные преобразования непрерывной позиции поля в `GridCoordinate` и центра клетки обратно в позицию поля. Начальная конфигурация: 12×8, cell size 1, координатное начало `(-6,-4)`.

`BattleGrid` создаётся из определения карты и `PathDefinition`. Он хранит состояния `Available`, `Blocked` и `Occupied`. При создании rasterization помечает все клетки каждого сегмента пути, включая промежуточные, как `Blocked`. Последующее строительство меняет только `Available` → `Occupied`; сам `PathDefinition` остаётся неизменным.

`TowerDefinitionId` идентифицирует тип башни, а strongly typed `TowerId` — уникальный экземпляр. `TowerDefinition` содержит ID, цену и минимальные базовые параметры range/fire rate/damage для следующих этапов. Конструктор отклоняет пустой ID, отрицательную цену и некорректные численные параметры. `TowerState` хранит `TowerId`, definition и координату.

`PlaceTowerCommand` содержит `TowerDefinitionId` и координату. `BattleSimulation.PlaceTower` последовательно проверяет фазу, определение, границы, доступность клетки и золото. Результат содержит успех, явную причину отказа и созданную башню при успехе. Только успешная команда атомарно создаёт следующий `TowerId`, списывает цену один раз, добавляет башню в read-only список `BattleState` и занимает клетку. Любой отказ не меняет состояние.

Начальное золото передаётся в существующий конструктор симуляции как настраиваемое значение; сценарий использует 150, тестовая башня — 60. Существующие вызовы P1.1 сохраняются через совместимые значения по умолчанию там, где это не скрывает конфигурацию. `StartWave` остаётся идемпотентным.

## Configuration

`BattleScenarioConfig` расширяется serialized-полями размеров и начала сетки, cell size, starting gold и параметрами одной тестовой башни. `CreateSimulation` преобразует их в Domain-объекты. Существующий `TestWave.asset` обновляется Unity serialization, без ручного изменения GUID. Waypoints остаются единым источником маршрута для Domain и Presentation.

## Presentation

`BattleSceneController` больше не запускает волну в `Start`. Он создаёт симуляцию в `Preparation`, управляет fixed-step циклом только в Combat и синхронизирует enemy/tower views с read-only состоянием.

Небольшой `BattlePlacementController` на том же Battle adapter отвечает только за ввод и выбор: pointer мыши/касания через установленный Input System, проверку UI через `EventSystem`, raycast на игровую плоскость и преобразование в клетку через Domain map. Первый тап по доступной клетке выбирает её и показывает выделение, preview башни и Confirm/Cancel. Cancel очищает только выбор. Confirm вызывает Domain-команду; prefab постоянной башни создаётся только после успеха. Недоступная клетка не создаёт покупку. Нажатия по UI не передаются на поле.

HUD показывает существующие статистики, Gold и кнопку Start Wave. После перехода в Combat placement selection очищается, Confirm/Cancel и строительство недоступны. Повторный Start Wave не создаёт дополнительных врагов.

`BattleSceneBuilder` обновляет существующую Battle сцену через Unity Editor/MCP: строительные клетки визуально различаются по состоянию, дорога остаётся видимой, добавляются оригинальный primitive placeholder тестовой башни, selection/preview и uGUI controls. Все ссылки и `.meta` сохраняются. Визуальный стиль остаётся graybox.

## Tests

Новые EditMode-тесты покрывают границы и преобразования сетки, дорогу и промежуточные сегменты, успешное размещение, занятость, вне карты, недостаток золота, однократное списание, повторную команду, некорректные определения, уникальность `TowerId`, неотрицательное золото и запрет строительства в Combat. Отдельно проверяются неизменность маршрута и конфигурационные значения.

Все тесты P1.1 запускаются без изменений их ожидаемого поведения, кроме явно заказанного ручного запуска волны в Presentation. Play Mode проверяет выбор без покупки, Cancel, Confirm, блокировку UI, недоступные клетки, Start Wave и прохождение пяти Shade по прежнему пути. Сохраняются Game View screenshots до и после строительства и результаты тестов. iOS export выполняется без signing при доступном модуле; физический iPhone не считается проверенным без реального device-запуска.

## Acceptance

- В Play Mode первый тап выбирает доступную клетку, Confirm строит одну башню, Cancel отменяет выбор.
- Дорога, промежуточные клетки пути, занятые и вне-карточные координаты отклоняются Domain.
- Золото списывается ровно один раз и никогда не становится отрицательным; повторная команда не меняет состояние.
- Маршрут не меняется после строительства; пять Shade проходят существующий путь после одного или повторных нажатий Start Wave.
- Все EditMode-тесты проходят, Unity Console не содержит ошибок, Domain не ссылается на `UnityEngine`.
- PR содержит архитектурные решения, точные команды и результаты, screenshots, ограничения проверки iOS и не merged.
