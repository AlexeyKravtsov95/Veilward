# P1.4c — Gameplay Validation & Balance Baseline: спецификация

## Scope и acceptance criteria

Проверяется существующий восьмиволновой graybox-матч на неизменённом `Assets/_Game/Configs/EightWave.asset`. Новые игровые механики, изменения баланса, Scene/Prefab/Config, Unity packages и редизайн UI не входят.

Готовый тикет должен содержать:

- три воспроизводимые стратегии A/B/C с командами строительства, Upgrade/Sell и пословновой телеметрией Gold, Base Health, kills/leaks и результата;
- хотя бы одну легальную механическую стратегию Victory либо воспроизводимый Defeat с доказанными ограничениями;
- компактный deterministic regression test на сохранённом `EightWave.asset`, сравнивающий два прогона по каждому тику, командам, Gold, TowerId/EnemyId и terminal result;
- реальный Editor Play Mode UI flow с кадрами landscape, включая последнюю волну и фактический terminal result;
- `Docs/P1.4C_BALANCE_REVIEW.md`, журналы и Console report в `Docs/review/P1.4c/`;
- положительные полные static, EditMode, PlayMode и `git diff --check` без скрытых skipped/inconclusive.

## Затронутые системы и риски

- Tests: новый EditMode replay/regression fixture; существующие Domain/Presentation не изменяются.
- QA/evidence: временные Editor/Play Mode runners вызывают только существующие публичные API и не входят в runtime.
- Docs: новый regression contract, strategy logs, screenshots, Console report и balance review.
- Риски: ложный PASS от синтетического config вместо saved asset; прямое изменение состояния; пропущенные AttackEvents; несовпадение механического replay и визуального сценария; нечитаемый HUD; изменение serialized assets во время тестов.

## Стратегии

Все стратегии начинаются с Preparation, 150 Gold, 20 Base Health, нулевых Tower/Enemy IDs и восьми сохранённых волн. Волны запускаются только `StartWave`/`ContinueToNextWave`; строительство и экономика выполняются только в Preparation через `PlaceTower`, `UpgradeTower`, `SellTower` либо соответствующие UI API.

- **A — Tower Expansion:** две стартовые L1 башни; между волнами приоритет новых L1 на заранее зафиксированных легальных клетках, upgrades и продажи не используются.
- **B — Tower Upgrades:** одна стартовая башня; приоритет L1→L2→L3, затем дополнительная башня и её upgrades по фиксированному правилу; продажи не используются.
- **C — Flexible Economy:** фиксированная последовательность строительства, upgrades и хотя бы одной продажи с rebuild на освобождённой клетке; выбор действий между волнами воспроизводим и зависит только от публичного состояния.

Точные координаты и команды фиксируются после первых механических прогонов и затем используются без изменений для deterministic replay и визуального прогона.

## Телеметрия и доказательства

После каждой волны сохраняются WaveIndex/Phase/Tick, Gold, Base Health, Kills, leaks в этой волне и состав башен с ID/координатой/Level/InvestedGold. Журнал команд включает цену каждой покупки/upgrade, refund каждой продажи и отклонённые команды. Kills и leaks различаются по изменению Kills и числу исчезнувших врагов без kill.

Скриптовые прогоны подтверждают только механическую проходимость и экономику. Отдельный Play Mode прогон проверяет Presentation и реальные кадры, но не объявляется субъективным человеческим playtest. Physical iPhone, touch/safe area, производительность, signing и Simulator остаются NOT VERIFIED без фактических запусков.

## Regression и Quality Gates

- `REG-BATTLE-051`: saved EightWave replay с экономикой детерминирован по полному timeline.
- `REG-BATTLE-052`: три сохранённые стратегии используют реальный config, штатные команды и дают воспроизводимые журналы/результаты.
- `REG-BATTLE-053`: Editor Play Mode подтверждает полный UI cycle и landscape HUD реальными screenshots.

Команды: `./Scripts/run-static-checks.sh`, `./Scripts/run-edit-mode-tests.sh`, `./Scripts/run-play-mode-tests.sh`, `git diff --check`. Дополнительно проверяются 0 compilation/Console errors, Missing Scripts, `.meta`/GUID, неизменность runtime `Assets` вне нового test, `Packages`, `ProjectSettings` и отсутствие новых зависимостей.
