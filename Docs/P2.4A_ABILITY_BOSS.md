## 3. Targeting, команды, validation

Координаты `PathPosition(X,Y)` — плоскость Domain, в Unity world XZ. Центр любой конечный point внутри **полуоткрытых** map bounds `[OriginX, OriginX+Width*CellSize) × [OriginY, OriginY+Height*CellSize)`. Для базы это `[-6,6) × [-4,4)`. Не snap к клетке; дорога/занятая клетка допустимы. Радиус может выходить за карту, центр не clamp: outside → отказ. Цели — все `IsAlive` в текущем `State.Enemies`, по Domain `Path.GetPosition(DistanceAlongPath)`, inclusive `distance² <= radius²`; нет Collider/hitbox/башен/будущих spawns. Расчёт distance² в double из float координат, без sqrt. Список на момент команды фиксируется в порядке **EnemyId ascending**, позиции captured до первого damage. Никакого First/nearest/camera order. Предел определяется validated общим числом spawns миссии; переиспользуемый буфер, без LINQ/list allocation на hot path.

Preview — только Presentation; показанный target count приблизителен до Confirm, не бронь врагов. Кнопка Confirm активна лишь с выбранным finite in-bounds point и ожидаемой целью, но Domain повторно проверяет всё. Pointer по UI не выбирает центр. World tap в режиме ability меняет центр; второй tap по полю сам не кастует. Отдельный Cancel/закрытие отменяют preview без gameplay mutation.

**Предлагаемые сигнатуры, не существующий API:**

```csharp
readonly struct CastAbilityCommand {
    AbilityDefinitionId AbilityId; // ровно rift-seal
    PathPosition Center;
    int ExpectedWaveIndex;        // zero-based, текущая Combat wave
    long ExpectedTick;            // текущий State.Tick на dispatch
    long ExpectedCastSequence;    // ожидаемый AbilityState.NextCastSequence
}
AbilityCastResult CheckCastAbility(CastAbilityCommand command); // read-only
AbilityCastResult CastAbility(CastAbilityCommand command);      // синхронно, атомарно
// Result: Succeeded, FailureReason, CastSequence?, HitCount, TotalAppliedHpLoss
// AbilityState: RulesId, AbilityId, CooldownRemainingTicks, NextCastSequence (read-only)
```

`AbilityDefinition` immutable/validated: known ID, Damage>0, finite Radius>0, CooldownTicks>0. Max accepted cooldown600 для D-01; произвольные значения из save запрещены. Вычисления damage через long/int saturation как текущий pipeline. Последовательность long положительная, начально1; при `long.MaxValue` команду отвергнуть до mutation, не wrap. Клиент не передаёт damage/radius/targets/cooldown. `PathPosition` constructor отвергает NaN/Infinity; внешняя input conversion даёт `InvalidTarget`, не исключение в Button callback.

Порядок отказов (первый побеждает):

| Порядок | Проверка | FailureReason |
|---:|---|---|
| 0 | Presentation: не paused/focused-background, разрешён свой owner, действующий одноразовый preview lease | `Paused`, `InputBlocked`, `ConfirmationRequired`/`StalePreview` (adapter result; Domain не знает UI) |
| 1 | Phase == Combat | `InvalidPhase` |
| 2 | Rules enabled; ID совпадает с definition (null/empty/default/unknown — unknown) | `AbilityDisabled`, затем `UnknownAbility` |
| 3 | ExpectedWaveIndex/Tick/NextCastSequence совпадают | `StaleCommand` |
| 4 | Remaining == 0 | `CooldownActive` |
| 5 | Finite center и bounds | `InvalidTarget` |
| 6 | Есть хотя бы одна живая цель в радиусе | `NoTargets` |
| 7 | NextCastSequence безопасно увеличить | `IdentifierExhausted` |

`Check` не резервирует успех; `Cast` повторяет те же проверки на текущем state. Любой отказ сохраняет целиком tick/phase/HP/Gold/Kills/IDs/army/grid/progression/ability и все event buffers/sequence. Неуспех не создаёт event, не запускает cooldown, не пишет safe save. Повторный Confirm после успеха — adapter ConfirmationRequired; прямой повтор команды — StaleCommand даже после600 ticks. Новый command в cooldown — CooldownActive. Новый command с новой последовательностью после cooldown допустим. ExpectedTick на Confirm берётся из актуального snapshot; ExpectedCastSequence и wave привязаны к началу preview. Preview инвалидируется при смене wave/ability sequence/Restore/scene session; старый callback не обновляет lease автоматически.

### 3.1 Время, lethal tick и атомарность

Cast — синхронная команда **между** Steps на основном orchestration thread, не deferred очередь. #36 не добавляет стадию в существующий Step и не меняет старый leak-before-tower порядок. Orchestrator выполняет накопленные fixed Steps/consume, затем dispatch Confirm в этом Update; если callbacks пришли раньше, записывает только input intent и разбирает после Steps. Повторные intents сериализуются, каждый проверяет phase/lease заново. Headless replay записывает точный command boundary относительно Step. Время VFX не влияет на попадание.

- Confirm до следующего Step может убить врага у выхода: умерший не leak-ает. Due Burn следующего Step на мёртвом не выполняется.
- Если Step уже довёл HP базы до0/Defeat (включая boss leak), последующий Confirm → InvalidPhase, без cooldown/damage/reward; способность не отменяет завершённый leak.
- На одном render frame с lethal Step и Confirm применяется указанное правило **Steps сначала**. На tick без Step, в т.ч. сразу после Start/spawn0, cast допустим. Это не extra simulation tick.
- Успех один раз потребляет sequence, устанавливает Remaining=600, публикует AbilityCastEvent, damage по captured ID order, затем **тот же общий death/removal/reward и completion/bonus handler**, что в Step. Если последняя цель убита и schedule исчерпан, WaveComplete/Victory наступает сразу, tick не меняется; если есть будущие spawns, остаётся Combat. Pending3/6 создаётся этим же общим handler. Нельзя дублировать логику начисления в UI/ability resolver.
- Каждый последующий Combat Step уменьшает Remaining на1 **перед** Spawn/Burn; после600 таких Steps Ready. Последний Combat Step, завершающий волну, тоже считается. Время вне Combat не считается. Способность не меняет tower attack cooldown, enemy IDs или simulation tick. Completion save вызывается controller после команды так же, как после Step.

## 4. Damage и события

Для каждого captured живого target: `effectiveArmor=max(0, Armor-Crack.Power)`; `raw=120`; `resolved=max(1, raw-effectiveArmor)`; `applied=min(HealthBefore,resolved)`; HP clamp0. Gust не множит, armor penetration0. Статусы не добавляются/не обновляются/не потребляются; `ReactionResolver` не вызывается, reaction windows не резервируются. Уже существующие статусы продолжаются у выживших. Burn/tower/reaction kill и ability kill сходятся в единственном `RemoveDefeatedEnemies`: Kills+1 и Reward один раз, saturated Gold. Leak удаляет без kill/reward. Способность по boss armor10 даёт110 до Crack; при HP50 applied50/overkill60, а не110 HP loss.

```csharp
// Append enum, сохраняя Direct=0, Burn=1, Reaction=2:
DamageOrigin.Ability = 3;
readonly struct AbilityCastEvent {
    long Tick; int SequenceInTick; AbilityDefinitionId AbilityId;
    long CastSequence; PathPosition Center; float Radius; int HitCount;
}
// DamageResolvedEvent получает optional append-only поля:
AbilityDefinitionId? SourceAbilityId; long? AbilityCastSequence;
// существующие Tick/Sequence/Origin/TargetEnemyId/positions/configured/raw/
// resolved/applied/healthAfter/WasLethal/ReactionKind/ReactionSequence/HitIndex сохранены
```

Ability hit: SourceAbilityId=`rift-seal`, AbilityCastSequence=accepted sequence; `SourceTowerId=default` — **не tower source**, никогда не конструировать фиктивную `TowerId(0)` и не искать башню. ReactionKind/ReactionSequence=null, HitIndex0…N-1; FromPosition=center, TargetPosition=captured point. Остальные origins имеют оба новых поля null и прежний tower source. Consumers обязаны сначала branch по Origin. Существующие constructor call sites сохраняются через optional overload/default arguments, старый AttackEvent не меняется и не выдаётся для ability. Новые поля не дописывать в historical trace format; новый observer сериализует все поля отдельно.

`AbilityCastEvent`, `ReactionEvent` и `DamageResolvedEvent` используют один возрастающий `SequenceInTick`; прежний `AttackEvent` остаётся отдельным stream без этого поля. Step reset только при **переходе к следующему tick**; cast между Steps продолжает sequence текущего tick, несколько casts на одном tick не получают одинаковых номеров. Clear не сбрасывает sequence; successful Restore очищает все buffers и начинает чистый event epoch, rejected Restore их не меняет. Cast event предшествует своим damage events. AbilityEvents — reused read-only list с явным ClearAbilityEvents; no auto-clear и no damage при чтении. Controller после **каждого Step и successful Cast** потребляет все четыре stream и чистит в одном finally, даже если в frame несколько Steps; никогда не теряет command-origin events до render. Lethal captured positions сохраняются после removal. Если cast завершил волну, сначала consume всех hits, затем UI phase/save; failed terminal save оставляет live result.

## 5. Босс и финальная волна

Оригинальное рабочее имя «Страж Разрыва», ID `rift-warden`; art/лицензии по ART_PIPELINE, модель этим PR не создаётся. В новой версии wave8 две validated группы: Shade count11/first0/interval30, boss count1/first330/interval30 (interval нужен валидатору даже для одной цели). Waves1…7 неизменны. Общее число12, boss ровно1 и только8. Общий порядок spawns `(relativeTick, groupIndex, spawnIndex)`; IDs назначаются в этом порядке. Проверять schedule sum/long overflow, last spawn, positive values, known enemy IDs, ровно один boss. Старая single-group constructor остаётся адаптером ровно одной группы; не превращать default/missing boss data в Shade.

Нужен минимальный multi-group `WaveDefinition`/cursor: один precomputed bounded schedule, без нового AI/spawner framework. CheckStartWave проверяет ID budget по **сумме** групп до phase mutation. Wave completion требует **все группы исчерпаны** и живых врагов нет; временная пустота до boss330 не даёт bonus/Victory. Начало8 по прежней отдельной кнопке, без автозапуска и наград открытия.

| Состояние босса/волны8 | Domain / economy | Presentation |
|---|---|---|

Если в lethal leak Step башни успели убить другую цель, её обычная kill reward сохраняется (существующий порядок); Defeat всё равно приоритетнее completion/bonus. Если Burn убил босса до Movement — kill, не leak. Ability после lethal leak не принята. Во всех случаях HP/Gold/Kills и event damage должны сходиться по EnemyId. Terminal не Continue-able, новый матч только New Game. Boss transient HP/statuses в checkpoint не вводятся.

## 6. Safe checkpoint, migration и content compatibility

### 6.1 Schema4 и DTO

```json
"ability": {
  "rulesId": "rift-seal-v1",
  "abilityId": "rift-seal",
  "cooldownRemainingTicks": 421,
  "nextCastSequence": 3
}
```

`BattleCheckpoint.ability` обязателен в schema4 во **всех** safe фазах, включая terminal. Definition damage/radius/cooldown, UI preview/lease/pointer, intents, event sequence/buffers, enemies/statuses/reaction windows и boss HP/spawn cursor не сериализуются. Export/Restore deep copy. Enabled: exact rules/id, `0<=remaining<=600`, `1<=nextCastSequence<=long.MaxValue`, remaining>0 требует sequence>=2. Initial pending start: remaining0/sequence1; прочие фазы сохраняют фактические значения. Не угадывать число casts из Kills/Gold. `nextCastSequence=long.MaxValue` — допустимый сохраняемый exhausted sentinel: все будущие casts отклоняются, но Export/Restore/Next по-прежнему возможны. Успех при MaxValue-1 переводит в этот sentinel без overflow. Disabled: **ровно** rules=`ability-disabled-v1`, abilityId=`none`, remaining0, sequence1. Неизвестные combinations, null/missing/duplicate keys, bool вместо числа, fraction/overflow/negative, unknown enum/content/extra ability fields отвергаются до публикации.

Schema bump3→4 нужен из-за обязательного состояния и строгого presence validation. Slot name остаётся `wave-checkpoint-v1.json`/`.tmp`/`.bak`; не переименовывать файл под schema. Остальные phase/tower/ID/экономика/progression constraints schema3 сохраняются. Новый content ID нужен из-за ability + заменённой wave8. Изменение чисел после выпуска этого content требует отдельного version/migration решения.

Это конечный production whitelist после #39. В #37–38 enabled persistence/UI проверяются с explicit internal `synthetic-p24-ability-v1` fixture, вне production whitelist/меню; final ID до появления полного boss schedule/factory отвергается. Подробности staged acceptance — план §1. Только New Game новой версии использует новый content. Запрос новой EightWave миссии принимает exact новый ID либо ровно старые `eight-wave-unlocks-v1`/`eight-wave-v1` для Continue; single-wave отдельно. MainMenu/Session/Store/Controller используют один whitelist и factory routing **до** Restore. Нельзя валидировать native primary одним factory, а legacy backup этим же native instance. Каждый слот независимо проходит весь путь; невалидный primary не мешает валидному backup другого разрешённого mode. Оба невалидны → понятный error/Continue disabled, live state и файлы не менять. Unknown/missing поля старого формата не превращать в defaults; отсутствие ability законно **только** у валидных schema1–3 входов в таблице.

Normalize/Load не записывают bytes, идемпотентны и не объединяют поля слотов. Следующий явный успешный Save пишет schema4 с **тем же** content ID и полной validation temp/read-back. Backup заменяется только предыдущим целиком валидным primary; corrupt primary не вытесняет valid backup. Rejected restore сохраняет State/Grid/ability/events/transients. Успешный restore заменяет всё одним действием и чистит все Domain/Presentation transients, а не частично cooldown.

## 7. Общий input/modal contract без click-through

Расширить **существующий** `BattleInputOwner`/`BattleSceneController.CanAcceptInput` owner `Ability`; не строить отдельную конкурирующую modal систему. Pause — верхний latch над любым owner. Остальные owners взаимоисключающие; обязательный ElementChoice восстанавливается из Domain pending раньше optional окон. Modal blocker uGUI и guard обязательны одновременно.

| Текущий owner | Вход/переходы | Заблокировано |
|---|---|---|
| None | BeginAbility только enabled/Combat/Ready; открыть Inspector; обычные phase-valid действия | Cast без preview; ability в Preparation/WaveComplete/terminal |
| Ability preview | World tap меняет центр; свой Confirm/Cancel; Pause/выход. Simulation продолжает идти. | Choice/Sell/Inspector/Placement, Upgrade/Build/Start/Next и чужие callbacks; повтор BeginAbility не создаёт второй lease |
| Inspector | Собственные world taps меняют EnemyId, miss поглощается; Close/Pause/выход | Ability Begin/Confirm до явного Close; tap закрытия не начинает ability |
| Placement | Свои Confirm/Cancel; существующая передача occupied tower selection read-only инспектору сохраняется | Ability до явного Cancel, чужие callbacks |
| Sell | Только свой Confirm/Cancel/Pause/выход | Ability/Choice/Inspector/Placement/переходы |
| ElementChoice | Свой Preview/Confirm/Cancel/Pause/выход; Cancel оставляет обязательный pending | Ability и вся экономика/Start/Next до completion выбора |
| Pause/background | Только Resume при focus/active или выход; pending Choice сохраняется, optional owners/preview/lease/intents очищаются | Все gameplay API и callbacks, world input, simulation/VFX clocks |

Ability preview имеет одноразовый lease `(sceneSessionEpoch, previewGeneration, expectedWave, expectedCastSequence)`. Generation меняется при каждом Begin/Cancel/Pause/Restore/phase-change, scene epoch при новой simulation; не сериализуются и не являются Domain RNG. Confirm сначала проверяет guard/lease, затем **потребляет lease до dispatch**. Повторная подписка Button/два pointer не могут сделать второй cast. На Domain отказ показать точную причину, очистить preview; повторная попытка требует нового Begin. Read-only CanCast не резервирует lease/targets. Внутренний owner route доступен только AbilityController; внешний public API не принимает произвольный owner для обхода guard. Direct Domain тесты не знают Pause, а direct public Scene/Ability APIs и `.onClick.Invoke` обязаны его учитывать.

При открытии/закрытии любого modal, Confirm/Cancel, Restore и Resume: consume triggering pointer ID **до его Up/Cancel включительно**, подавить world dispatch текущего frame; для touch и mouse. Pointer, удержанный сквозь Pause/Resume или смену owner, требует нового Down после отпускания. Два пальца не делят один lease; второе касание во время UI/modal не превращается в world tap. Не полагаться только на `EventSystem.IsPointerOverGameObject` в момент Up: owner мог уже исчезнуть. Safe-area controls, fullscreen blockers и EventSystem raycasts сохраняются. Pause очищает accumulator/первый resumed delta и замораживает VFX clock; Time.timeScale не меняется. Автоматическое завершение Combat во время preview отменяет lease; при возникновении Choice3/6 owner переключается на обязательный Choice без выбранной карточки. Restore/Continue/New Game чистят preview, inspector, placement, pending Sell, intent queue, ability/reaction VFX/summary, beams и event streams.
